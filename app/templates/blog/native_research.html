Research that fits each device

The native apps are being built around company research: find a company, inspect a historical figure, follow the filing evidence, and keep a note for later.

October 3, 2026 · Development update

One research flow, three interfaces

Mac uses a sidebar, financial tables, a source inspector and separate comparison windows. Keyboard actions keep search, refresh and notes close to the work. iPhone uses tab navigation, reporting-period lists and source sheets. Android uses Kotlin and Material controls, with a list-and-detail layout when the window has enough room.

The Apple targets use Swift and SwiftUI. The Android target uses Kotlin and Jetpack Compose. The same historical financial contract supplies periods, units, calculation methods and SEC filing links.

Research saved on the device

Reports and notes are stored locally for offline reading. A note keeps the selected metric, period, report version and filing sources. Refresh is explicit, and newly reported or revised values are compared with a saved review baseline. A missing value remains unavailable; a reported zero remains a value.

The public research API returns financial disclosures and provenance. It does not return private web accounts or workbooks, and it makes no paid AI calls. Local research does not automatically sync into a web account.

Current availability

These are development targets in the open-source repository. They are not available in the App Store or Google Play. The Mac preview has been exercised with synthetic data; iPhone code has passed source compilation checks. Full Android and phone-device validation remain pending.

Widgets, notification delivery, share extensions, cloud sync and provider chat are outside this first increment. The website remains available while native development continues.
